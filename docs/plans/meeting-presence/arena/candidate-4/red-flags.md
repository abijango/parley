# Red-flag screen (candidate 4 — auto-admit present)

**Shallow module.** The public roster surface is `MeetingAdmission` (`ingest`, TokenField diff, chip admit/dismiss, speaker-ID, restore). That is small relative to what it hides: Teams section split, snapshot emptiness, person vs room, session exclusions, old-bag restore, comma-safe names. The inspector does not coordinate merge + accept + filter. `MeetingMetadataResolver` stays a clock by design; depth moved to admission rather than thickening the timer. Risk: `RecordingController` growing pass-through wrappers (`acceptSuggestion` → `admitUncertain`). The sketch deletes those methods and lets the chip view call admission. If implementation reintroduces controller facades with the same signatures as admission, reject them.

**Information leakage.** AX types and `TeamsRosterParse.invited` stop at Detection. `MeetingSighting` has no invited field, so UI cannot "just show them." Title source is an enum, not a stringly calendar protocol. `SuggestedAttendee` remains a decode-only Codable type so old manifests work; the live path stops writing it. Leakage to watch: copying `accepted`/`dismissed` onto `UncertainChip` until it becomes the old bag again — dismissed is a chip flag, not a stand-in for present people. Name-classification heuristics live in one `NameClassifier`, not in Teams/Zoom/Webex parsers and not in the view.

**Temporal decomposition.** Not a scan → parse → merge sandwich with the same `RosterEntry` at every stage. Parsers own section grammar; admission owns who enters the note; the session object is a published projection. Ingest and token-field commits run at different times in the same module because they protect the same decision (who is on `attendees` and who cannot be refilled).

**Pass-through method.** `addAttendeeIfAbsent` becomes `admission.addRecognized` — same write, with exclusion policy. `onUpdate` does not reimplement admit. `SessionStore.stamped` still copies fields into a struct; that is serialization, not a second admission. No `MeetingSource` protocol whose `roster()` forwards to parsers.

**Shape discipline.** This is not a chip filter on the current bag (A), not a present-now ledger (B), and not per-app sources (C). Present people have no chip type. Invited names have no public field. Undo is exclusion on the attendee string, not a recommendation state machine.
