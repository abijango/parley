The shape passes the four red-flag screens. `PresenceLedger` is not shallow: one command surface hides snapshot completeness, partial leases, first observation, departures, deduplication, recommendation/admission/suppression policy, accepted ordering, and idempotency; each caller intent completes in one operation. Information does not leak: AX nodes, section anchors, pids, timeout mechanics, and calendar/title ranking remain in detection, while the UI receives only ledger projections and manifest migration is isolated in one adapter. The modules are organized by owned knowledge rather than scan order: parsing owns meaning extraction, the ledger owns person history and decisions, and persistence owns schema adaptation, so there is no load/validate/merge temporal pipeline sharing one representation. The controller’s `applyPresence` adapter is not pass-through because it converts a domain change into published state, the legacy attendee projection, and persistence scheduling; no other proposed method merely forwards the same arguments. The deliberate residual seam is the temporary comma-delimited attendee projection, but comma safety is enforced by `PersonName` and the string is derived from ledger-owned acceptance rather than synchronized as a second authority.
